You are synthesizing an LPCL v1 library performance contract from extracted evidence.

Return YAML or JSON only. Do not return prose.

Hard requirements:
- version must be "lpcl/v1"
- type must be "library"
- include top-level fields: version, contract, type, components, uses, assumptions, controls, signals, recipes
- every component, use, assumption, control, signal, and recipe must include evidence
- if evidence is weak or unrelated to resource contention, omit the claim
- prefer fewer, higher-quality declarations over weak coverage

Do not create new resource names.

The only valid resources are:
- cpu.compute
- cpu.placement
- gpu.compute
- gpu.memory
- mem.capacity
- mem.bandwidth
- io.bandwidth
- io.queue

Model implementation mechanisms as components, not resources.

If the source mentions threads, workers, thread pools, task pools, OpenMP teams, TBB arenas, queues, streams, backends, allocators, scratchpads, or caches, model them as components unless they directly refer to one of the valid shared resources.

Component rules:
- component.kind must be one of: executor, queue, allocator, backend, cache
- component.attrs is descriptive only
- thread and worker counts belong on executor attrs/workers and cpu.compute demand.dimension=workers

Mapping rules:
1. Model worker/thread count as:
   - component kind: executor
   - attribute: workers
   - use resource: cpu.compute
   - demand dimension: workers
2. Model CPU affinity/pinning as:
   - use resource: cpu.placement
   - demand dimension: core_set
3. Model GPU device use as:
   - use resource: gpu.compute
4. Model GPU memory/workspace/scratchpad as:
   - use resource: gpu.memory
5. Model host memory footprint/cache/buffer capacity as:
   - use resource: mem.capacity
6. Model memory traffic/bandwidth pressure as:
   - use resource: mem.bandwidth
7. Model I/O throughput as:
   - use resource: io.bandwidth
8. Model I/O queue depth/concurrency as:
   - use resource: io.queue

Use schema:
- use.resource must be one of the valid resources
- use.by must reference an existing component id
- use.phase must be one of: init, compute, communication, flush, background, teardown, unknown
- use.scope must be one of: thread, process, library, device, system
- use.share must be one of: shared, exclusive, partitioned, process_global

Demand schemas:
- cpu.compute -> {dimension: workers, min: <number_or_symbol>, max: <number_or_symbol>}
- cpu.placement -> {dimension: core_set, source: <string_or_symbol>}
- gpu.compute -> {dimension: devices, min, max} OR {dimension: partition, source}
- gpu.memory -> {dimension: bytes, min, max}
- mem.capacity -> {dimension: bytes, min, max}
- mem.bandwidth -> {dimension: intensity, value: <number_or_symbol_or_unknown>}
- io.bandwidth -> {dimension: bandwidth, min, max}
- io.queue -> {dimension: depth, min, max}

Assumption rules:
- predicate.kind must be one of: total_at_most, competitors_at_most, exclusive, not_nested, placement_compatible

- placement_compatible is valid only for cpu.placement

Control rules:

- control.type must be one of: int, float, bool, string, enum, set

Signal rules:
- signal.probe.kind must be one of: api, perf, os, log, profiler, benchmark, manual
- signal.probe.name must be the canonical probe name

Recipe rules:
- recipe.for must be one of:
  - shared_cpu_compute_conflict
  - cpu_placement_conflict
  - shared_gpu_compute_conflict
  - gpu_memory_pressure
  - host_memory_capacity_pressure

  - io_bandwidth_contention
  - io_queue_contention
