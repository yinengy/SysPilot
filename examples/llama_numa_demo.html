Innovation: Dynamic Script Generation

Profiling tools like strace and perf produce thousands of lines of dense output. This raw data far exceeds LLM context windows. SysPilot's agent solves this by writing custom processing scripts on-the-fly — sampling the data, generating a tailored parser, and extracting only essential metrics.

Why is this novel? The LLM never sees the full raw data — it writes code to compress it.

import re
from collections import Counter

lines = raw_data.strip().split('\n')
syscalls = Counter()
slow_calls = []
errors = 0

for line in lines:
    m = re.match(r'(\w+)\(', line)
    if m: syscalls[m.group(1)] += 1
    if '= -1' in line: errors += 1
    t = re.search(r'<([\d.]+)>', line)
    if t and float(t.group(1)) > 0.1:
        slow_calls.append(line.strip()[:60])

print(f"Total syscalls: {len(lines)}")
print(f"Unique types: {len(syscalls)}")
print(f"Top 5: {syscalls.most_common(5)}")
print(f"Errors: {errors}")
print(f"Slow (>100ms): {len(slow_calls)}")

📘 numactl Manual (excerpt)

manual/numactl.md
Target Brief
numactl is a Linux utility for controlling NUMA policy
and memory/CPU affinity for processes.
Critical System Resources
NUMA Topology
  Check: numactl --hardware
  Impact: HIGH - Wrong placement causes 2-3x latency

Memory Binding
  Check: cat /proc/<pid>/numa_maps
  Impact: CRITICAL - Remote memory is 2-3x slower
Tuning Decision Tree
Is workload memory bandwidth-bound?
 ├─ YES → numactl --interleave=all     ← OUR CASE
 └─ NO  → Is workload latency-sensitive?
           ├─ YES → --cpunodebind=X --membind=X
           └─ NO  → Check thread count ...
Key Policies
--interleave=all   Round-robin pages across nodes
--membind=N        Force memory on node N
--cpunodebind=N    Run threads on node N only
--preferred=N      Prefer node N, fallback allowed

⚡ eBPF Writing Skill — BCC Example

Agent-generated BCC Python script
from bcc import BPF
import time, ctypes as ct

bpf_text = """
#include <uapi/linux/ptrace.h>

BPF_ARRAY(cache_refs, u64, 1);
BPF_ARRAY(cache_misses, u64, 1);

int on_cache_ref(struct bpf_perf_event_data *ctx) {
    u32 key = 0;
    u64 *val = cache_refs.lookup(&key);
    if (val) { (*val)++; }
    return 0;
}

int on_cache_miss(struct bpf_perf_event_data *ctx) {
    u32 key = 0;
    u64 *val = cache_misses.lookup(&key);
    if (val) { (*val)++; }
    return 0;
}
"""

b = BPF(text=bpf_text)
b.attach_perf_event(
    ev_type=BPF.PERF_TYPE_HARDWARE,
    ev_config=BPF.PERF_COUNT_HW_CACHE_REFERENCES,
    fn_name="on_cache_ref", sample_period=1000)
b.attach_perf_event(
    ev_type=BPF.PERF_TYPE_HARDWARE,
    ev_config=BPF.PERF_COUNT_HW_CACHE_MISSES,
    fn_name="on_cache_miss", sample_period=1000)

print("Profiling cache performance for 3s...")
time.sleep(3)

refs = b["cache_refs"][ct.c_int(0)].value
misses = b["cache_misses"][ct.c_int(0)].value
rate = (misses / refs * 100) if refs > 0 else 0

print(f"Cache refs:   {refs:,}")
print(f"Cache misses: {misses:,}")
print(f"Miss rate:    {rate:.2f}%")

🛠️ Tuning Engine — Iterative Loop

Converges to optimal configuration

Tuning is not a one-shot operation. The engine runs an iterative loop — each cycle applies a candidate configuration, re-profiles the application, and feeds results back to the agent for the next decision.

📊
1. Profile Baseline
Collect performance metrics (t/s, latency, stddev)
🧠
2. Agent Decides
Analyzes results + manual → picks next configuration
⚙️
3. Apply Config
e.g. numactl --interleave=all
🔬
4. Re-Profile & Compare
Improved? → Accept. Worse? → Revert & try another.
🔄 Repeat until converged or no further improvement
Example (this demo): Iteration 1 baseline = 7.33 t/s → Agent picks --interleave=all → Re-profile = 9.13 t/s (+25%) → Accepted ✓
